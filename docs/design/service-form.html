3 · Add or edit a service

FR-6, FR-7, FR-33 to FR-74, FR-104 to FR-106. One form for both. Separate fields only (no raw editor, no paste-a-curl). The whole form works without a mouse: Tab order follows the page, rows are added and removed with buttons, and Enter in a single-line field saves. Full forms are drawn once each; other states draw only the region that changes.

Add service: idle (HTTP)createService

New service with defaults: HTTP(S), GET, timing 60 / 10 / 2 / 10, alerts on, public off. HTTPS options are unavailable until the URL starts with https://. Focus starts in Name; the outline is drawn there. Desktop: the test panel stays beside the form; 360 px: it follows the form. The footer with Cancel and Save sticks to the bottom of the window.

Edit service: every saved value shown (HTTP)getServiceupdateService

Editing shows every saved value, including header values in full (FR-39): the Authorization value is not masked. Rows: Tab moves through name → value → Remove; “Add …” inserts a row and moves focus to its first input; Remove moves focus to the next row’s first input, or to “Add …” when none is left.

Add service: TCP portcreateService

Choosing TCP port swaps the request, rules and HTTPS groups for Host and Port. The HTTP values stay in memory until saving, in case the admin switches back (only the chosen type is sent).

HTTPS options with an http:// URL PartialFR-104 to FR-106 · 422 requires_https_url

Both switches are disabled with a reason. If the server still returns requires_https_url (for example the URL was changed after a switch was turned on), the error shows on the switch’s field.

Body: JSON selected Partial

A body type other than None shows the body text area (monospace, up to 64 KB).

Saving PartialcreateService / updateService (pending)

Save shows a spinner and both footer buttons are disabled. Fields are read-only until the response arrives, so what is saved is what is on screen.

Saved PartialcreateService 201 / updateService 200

Returns to the dashboard with a toast; a new service appears as “Not checked yet”. See Dashboard › After save.

Field errors from the server Partial422 validation_failed · errors[].field, errors[].code

Each error shows on its field, including fields inside rows: headers[2].value → “Header 3 value”. A summary at the top lists them as links that move focus to the field; focus moves to the summary on submit. The timing rule (check_budget_exceeded, field settings) belongs to the Timing group as a whole. Errors clear when that field is edited. Wording per code is in the table at the end.

Field errors: rows and ranges Partial422 too_many · out_of_range · invalid_value

too_many on a row list shows under that list. out_of_range shows on the field without numbers, because the limits differ per install and aren’t readable (question 2).

Name already used PartialcreateService / updateService 409 service_name_taken

Shown on the Name field. Names are compared ignoring case.

Service limit reached PartialcreateService 409 service_limit_reached

Form-level banner. The typed values stay, so nothing is lost if the admin deletes a service in another tab and saves again.

Request too large Partial413 payload_too_large

Over 1 MB in total. Points at the fields that are most likely to be large.

Test running PartialtestServiceCheck (pending)

Only the test button is disabled; the form stays editable. Saving is still possible.

Test result healthy: long body, cut off PartialtestServiceCheck 200 healthy · response_body_truncated

Status, duration and HTTP status. The body is plain text in a scrollable box (focusable, so it scrolls with the keyboard) with a “cut off” notice.

Test result healthy: no body PartialtestServiceCheck 200 healthy, empty response_body

Test result failed: HTTP error with body PartialtestServiceCheck 200 healthy=false

A failed test is not an HTTP error. The HTML body is shown as text, never rendered (NFR-7).

Test result failed: timed out PartialtestServiceCheck 200 healthy=false, no http_status

Test refused: fields invalid PartialtestServiceCheck 422 validation_failed

The same field errors as on save are shown on the fields; the panel says the test did not run.

Service not found PartialgetService / updateService / testServiceCheck 404 not_found

Deleted meanwhile (for example in another tab). Save is disabled; the values stay visible so they can be copied.

Session expired Partial401 unauthenticated

Goes to Sign-in (Sign-in › Session expired). Typed values are lost unless question 5 says otherwise, so the leave-form confirmation is not shown here.

Request not accepted / unexpected error Partial403 csrf_failed400 malformed_request415 unsupported_media_typenetwork / 5xx

csrf_failed asks for a reload. 400/415 aren’t reachable from the form, so they share the generic message with network and 5xx errors.

Leave with unsaved changes (proposed)client only

Shown on Cancel, the back link, Sign out or Esc when the form differs from what was loaded. Focus starts on “Keep editing”. Closing or reloading the tab uses the browser’s own beforeunload prompt.

requiredEnter a {field}. / Required.
too_longToo long. (Name, messages: “Use 100 / 500 characters or fewer.”, see question 2)
out_of_rangeOutside the range this server allows. (Port: “Must be between 1 and 65535.”)
too_manyToo many rows. Remove some to save.
invalid_formatURL: “Enter a URL that starts with http:// or https://.” Email: “Enter a valid email address.” Other: “Not in the expected format.”
invalid_valueNot an allowed value.
requires_https_urlNeeds a URL that starts with https://.
check_budget_exceeded (field settings)On the Timing group: “The longest attempt is longer than the check interval…”

Field paths map to labels: headers[2].value → “Header 3 value”, query_params[0].name → “Query parameter 1 name”, json_rules[1].path → “Rule 2 field path”. Exact path syntax to be confirmed against openapi.yaml.
