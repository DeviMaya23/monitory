1 · Sign-in

FR-1, FR-2, FR-97. Username, password, submit. No sign-up, password reset or password change. Every message appears in one banner slot above the fields, so the form never shifts below it.

  • Idle
  • Submitting
  • Wrong credentials
  • Locked after 5 failures
  • HTTPS required
  • Server unreachable or unexpected error
  • Session expired or signed out

IdlesignIn

Focus starts in Username. Tab order: Username → Password → Sign in. Enter in either field submits. The focus outline is drawn on Username here.

SubmittingsignIn (pending)

Fields and button are disabled while the request is in flight; the button shows a spinner and “Signing in…”. Focus stays on the button.

Wrong credentialssignIn 401 invalid_credentials

One message that never says which field was wrong. The password is cleared and focus moves to Password; the banner is announced (aria-live).

Locked after 5 failuressignIn 429 sign_in_locked + Retry-After

Retry-After (seconds) drives a countdown, shown in minutes and seconds. The button stays disabled until it reaches zero, then the banner is removed.

HTTPS requiredsignIn 403 https_required + detail

The server’s detail is shown verbatim as plain text (NFR-7), in monospace so commands and setting names stay readable. The detail text drawn here is a placeholder, not the server’s real wording.

Server unreachable or unexpected errornetwork failure / 5xx (no contract source)

One generic message with a retry. Retry resubmits the same values.

Session expired or signed outany gated operation 401 unauthenticated

Where every admin screen lands on 401. After sign-in the app returns to the screen the admin was on. The notice is not shown after a deliberate sign-out.
